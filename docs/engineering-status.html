Architecture

Browser (console.html) │ signed invite-code cookie → tenant resolved SERVER-SIDE ▼ Vercel proxy (website/api/*.mjs) holds HERMES_API_KEY; browser never sees it ▼ Hermes gateway LLM manager; spawns specialist sub-agents ▼ MCP over stdio agents/mcp_server.py 8 tools, tenant guard at each entry point ▼ Agent fleet Engineer · Director · Sales · Research · Orchestrator │ each an Agent subclass with its own prompt + tool loop ▼ ghost/ llm · trace · config evals/ bundle · checks · judge · runner

Two layers of sub-agent, deliberately. The Hermes manager never calls a build tool itself — it spawns a delegate_task sub-agent per role ("You are the Engineer…"). That sub-agent calls one MCP tool, which instantiates the real Python Engineer/Director/Sales class — each running its own multi-step LLM tool-calling loop. The outer layer is orchestration; the inner is the actual work.

The guarantee that shapes everything

Never trust a tool's self-report. The dominant bug class in this codebase is "the tool returned success and the artifact is dead". It recurred often enough that the entire eval framework is built around structurally preventing it rather than catching it by review.

Concretely: every check re-fetches or re-opens the real artifact. Deterministic checks are hard gates — the LLM judge is never invoked on an artifact that already failed them, because a judge cannot rescue a dead link.

Why the judge can't fool itself

An LLM judge that hallucinates evidence is worse than no judge — it produces confident, unfounded numbers. Every criterion score must cite exact substrings from the real artifact. Citations are verified by literal substring match (whitespace/case normalised, deliberately not fuzzy). An unverified citation forces that criterion to zero, regardless of the score claimed. The same mechanism is reused for learned preferences.

Multi-tenancy (4 phases)

PhaseDeliversDesign note
1State isolation
agents/tenancy.py		Tenant key = slug(startup), derived from an argument the tools already carry — no new plumbing. Path traversal contained by re-slugging; 7 hostile inputs tested.
2Per-tenant briefing cacheTenant derived from ingested product_name, so all 14 summary() call sites benefit without change. Invalidated by a sha256 over ingested content.
3Learned preferencesQuote-verified extraction (see above). Capped at 40 and deduped so prompts can't grow unbounded.
4AuthorizationREVENANT_PINNED_TENANT. Refuses cross-tenant calls rather than silently redirecting.

Read this before assuming the system is multi-tenant-safe. The tenant reaches the tools as an argument that travels through an LLM. An LLM can be talked out of an instruction. The console-side tenant injection is defence in depth, not a security boundary.

The real boundary is REVENANT_PINNED_TENANT: an environment variable set at process spawn, which cannot be argued with. The intended deployment is one pinned MCP server per customer. Verified over real MCP stdio: a pinned server refuses a call whose argument explicitly names another tenant.

Currently unpinned in the running deployment — safe today (single operator, single authenticated gateway), must be enabled before customer #2.

Observability

Pluggable tracing behind one shim (ghost/trace.py): jsonl by default, langfuse when configured — and jsonl keeps writing alongside it, so a misbehaving backend never loses tracing.

Verified live against a real Langfuse project. Traces carry: user_id = tenant, session_id = tenant:merchant (one campaign), tags, environment, git-sha release, specific observation types (agent / generation / retriever / evaluator), model and token usage for cost attribution.

Sensitive data is masked before leaving the process — emails, API-key shapes, bearer credentials. Confirmed on real data: a prospect address arrived as <email-redacted>. Masking is regex-over-payload rather than field-aware, because a field-aware masker only redacts the keys someone remembered to list.

Bugs worth knowing about

All found by running the system, not by reading it. Listed because each represents a class, not a one-off.

BugWhy it mattered
Judge ran in offline modeReturned a canned stub; the zero-score path skips citation checks by design, so a fake 0.0/100 was indistinguishable from a real harsh verdict. Real score was 22.5.
Score with no anchorEvery eval score silently 400'd into Langfuse — SDK logged it, the never-raise contract swallowed it. Found on the first live run.

Cross-thread span nestingEvery span inside a worker thread started a new root trace. 14 spans → 14 traces; now 1.
Dotted invite codeAccepted at login with a 200, then 401'd forever. Silent permanent lockout.
Gateway outlived its MCP subprocessLive console reported "tool not available". Operational failure mode — worth alerting on.

Operational notes

  • Secrets: .env (gitignored, mode 600). Browser never receives a key — the Vercel proxy holds them. The current Langfuse key pair was pasted into a chat transcript and should be rotated.
  • Gateway health: it can outlive its MCP subprocess and report tools as missing. A restart fixes it; this deserves monitoring.
  • Degraded mode is normal: missing enrichment keys degrade gracefully (guessed emails, macOS voice, no payment link) rather than failing — check status before assuming a feature is broken.
  • Prompt changes: bump PROMPT_VERSION and regenerate the baseline; a T0 guard enforces this.
